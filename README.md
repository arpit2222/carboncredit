# VeChain Carbon Credit NFT System

## Overview
Blockchain-based carbon credit tracking system built on VeChain for the VeChain Builders Hackathon. This project tokenizes carbon credits as NFTs, enabling transparent verification, trading, and retirement of carbon offsets generated by farmers and organizations.

## Architecture
This is Phase 1 of the project, implementing the core NFT contract for carbon credits. Future phases will include:
- **Phase 2**: Organization & Farmer Registry contracts
- **Phase 3**: Carbon Credit Verification workflow
- **Phase 4**: VeChain Fee Delegation (VIP-191) integration ✅
- **Phase 5**: VeBetter DAO B3TR token rewards ✅
- **Phase 6**: Wanchain Bridge Compatibility and Cross-Chain Support ✅
- **Phase 7**: JavaScript SDK and frontend integration

## Phase 6: Wanchain Bridge Compatibility and Cross-Chain Support ✅

### Features
- **Cross-Chain Bridge Support**: Lock/unlock carbon credit NFTs for cross-chain transfers
- **Wanchain XFlows Integration**: JavaScript integration with Wanchain XFlows API
- **Bridge Event Management**: Real-time bridge event monitoring and metadata sync
- **Transfer Restrictions**: Prevent transfers of locked tokens during bridge operations
- **Bridge Status Tracking**: Comprehensive bridge status and transaction tracking
- **Multi-Chain Support**: Bridge to Ethereum, Polygon, BSC, and other supported chains

### Smart Contract: Enhanced `CarbonCreditNFT.sol`

#### New Bridge Functions
- `lockTokenForBridge()`: Lock token for cross-chain bridging
- `unlockTokenFromBridge()`: Unlock token after successful bridge
- `updateBridgeStatus()`: Update bridge status (pending/bridging/completed/failed)
- `isTokenLocked()`: Check if token is locked for bridging
- `getBridgeInfo()`: Get comprehensive bridge information
- `getBridgeStatistics()`: Get bridge statistics and metrics

#### Bridge Status Enum
- **None**: No bridge operation
- **Locked**: Token locked for bridge
- **Bridging**: Token in transit
- **Unlocked**: Token successfully bridged
- **Failed**: Bridge operation failed

### JavaScript Integration

#### WanchainBridgeManager Class
- **Token Discovery**: Discover supported tokens for bridging
- **Quote Generation**: Get bridge quotes with fees and timing
- **Transaction Building**: Build bridge transactions
- **Status Tracking**: Track bridge transaction status
- **Event Monitoring**: Real-time bridge event monitoring

#### CarbonCreditBridgeManager Class
- **Specialized Bridge Operations**: Bridge carbon credit NFTs specifically
- **Bridge History**: Get carbon credit bridge history
- **Status Checking**: Check bridge status for specific tokens

#### BridgeEventManager Class
- **Event Subscription**: Subscribe to bridge events with filters
- **Metadata Sync**: Cross-chain metadata synchronization
- **Event History**: Bridge event history and analytics
- **Statistics**: Bridge statistics and metrics

- `calculateReward()`: Calculate B3TR rewards for carbon credits

- **Base Reward**: 100 B3TR per tonne of carbon credit
- **Verified Bonus**: 150% bonus for verified credits (250 B3TR total per tonne)

- **CarbonCreditNFT**: Reads metadata for reward calculation
- **CarbonCreditVerifier**: Validates verification status for bonuses

## Phase 1: Carbon Credit NFT Contract

### Features
- **ERC-721 NFT standard** for unique carbon credits
- **Rich metadata**: Carbon amount, location, verification status, project type, generation date, IPFS proofs
- **Role-based access control**: Minter, burner, and admin roles
- **Retirement mechanism**: Credits can be retired (marked as offset) without burning
- **IPFS integration**: Store verification documents and IoT data off-chain
- **VeChain-optimized**: Deployed on VeChainThor with future fee delegation support

### Smart Contract: `CarbonCreditNFT.sol`

#### Key Functions
- `mintCarbonCredit()`: Mint new carbon credit NFT (MINTER_ROLE only)
- `burnCarbonCredit()`: Burn/destroy a credit (BURNER_ROLE or owner)
- `retireCarbonCredit()`: Mark credit as retired/offset (owner only)
- `updateVerificationStatus()`: Update verification status (MINTER_ROLE)
- `getCreditMetadata()`: Retrieve full credit metadata

#### Metadata Structure
The `CarbonCreditMetadata` struct contains:
- `creditId`: Unique identifier (same as tokenId)
- `carbonAmount`: Amount in tonnes CO2 (wei-like precision: 1e18 = 1 tonne)
- `generatorAddress`: Farmer or organization who generated the credit
- `location`: Geographic location (lat/long string or region name)
- `verificationStatus`: Current verification status (Pending, Verified, Rejected, Retired)
- `generationDate`: Unix timestamp when carbon was captured/offset
- `expiryDate`: Unix timestamp when credit expires (0 if no expiry)
- `projectType`: Type of carbon project
- `proofsIPFSHash`: IPFS CID pointing to verification documents/IoT data

#### Enums
- **VerificationStatus**: Pending, Verified, Rejected, Retired
- **ProjectType**: Reforestation, RenewableEnergy, SoilCarbon, Biochar, Other

#### Events
- `CarbonCreditMinted(uint256 indexed tokenId, address indexed generator, uint256 carbonAmount, ProjectType projectType)`
- `CarbonCreditBurned(uint256 indexed tokenId, address indexed burner, uint256 carbonAmount)`
- `CarbonCreditRetired(uint256 indexed tokenId, address indexed owner, uint256 carbonAmount)`
- `VerificationStatusUpdated(uint256 indexed tokenId, VerificationStatus oldStatus, VerificationStatus newStatus)`

## Setup Instructions

### Prerequisites
- Node.js >= 20.0.0
- npm or yarn
- VeChain wallet with testnet VET/VTHO (get from [faucet](https://faucet.vechain.org))

### Installation
```bash
npm install
```

### Configuration
1. Copy `env.example` to `.env`
2. Add your private keys (NEVER commit `.env`)
3. Configure IPFS API keys if needed

### Compilation
```bash
npm run compile
```

### Testing
```bash
npm test
```

### Deployment

**Testnet**:
```bash
npm run deploy:testnet
```

**Mainnet** (use with caution):
```bash
npm run deploy:mainnet
```

**Local Thor Solo**:
```bash
npm run deploy:solo
```

Deployment artifacts are saved to `deployments/CarbonCreditNFT-{network}.json`.
